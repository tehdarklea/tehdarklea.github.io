How to Detect Fake LLM API Providers Before They Drain Your Budget

Don't let resellers sell you GPT-4 while serving GPT-3.5. Here's how to catch them — and a free tool that does it automatically.

The $2.3B Problem No One Talks About

The LLM API reselling market is booming. Third-party providers offer "discounted" access to GPT-4, Claude, Gemini, and other frontier models through their own endpoints. Sounds great — until you realize what's actually happening behind the curtain.

Model substitution is the most common fraud: you pay for GPT-4, but the provider silently routes your request to GPT-3.5-turbo or an even cheaper model. The price difference? GPT-4 costs ~$30/1M output tokens vs GPT-3.5-turbo at ~$0.50/1M. That's a 60x margin for the reseller — and you're none the wiser.

But model swapping is just the beginning. Here are the four ways API resellers silently steal from you:

1. Model Substitution

You request gpt-4, they serve gpt-3.5-turbo. The response looks plausible, but it's cheaper, less capable, and not what you paid for. Some providers even fine-tune smaller models to mimic larger ones' output style.

2. Token Inflation

Your prompt is 500 tokens. The provider reports 800 input tokens and 1,200 output tokens. They inflate both sides of the ledger, charging you for tokens that were never processed.

3. Speed Throttling

They advertise "GPT-4 at half price" — because they're rate-limiting your requests to a fraction of what the real API provides. You save money per token but lose it in throughput and latency.

4. The Relay Chain

Your request doesn't go directly to OpenAI. It bounces through Provider A → Provider B → Provider C → OpenAI. Each hop adds latency, reduces reliability, and gives every intermediary a chance to peek at your data.

4 Methods to Detect Fake LLM APIs

Method 1: Header Analysis

Real API providers return specific headers. OpenAI includes openai-organization, x-ratelimit-remaining-tokens, and other identifying fields. If you're supposedly hitting OpenAI's API through a reseller but see none of these headers — or worse, see headers from a completely different provider — something's wrong.

import requests

response = requests.post(
    "https://your-reseller.com/v1/chat/completions",
    headers={"Authorization": "Bearer sk-xxx"},
    json={"model": "gpt-4", "messages": [{"role": "user", "content": "test"}]}
)

# Check for direct API headers
suspicious = not any(
    h.startswith("x-ratelimit") or h.startswith("openai")
    for h in response.headers
)

Method 2: Token Count Verification

Compare the reported token usage against your own count. Use a tokenizer (tiktoken for OpenAI models) to count tokens locally, then check if the API's usage field matches.

import tiktoken

encoding = tiktoken.encoding_for_model("gpt-4")
actual_tokens = len(encoding.encode(your_prompt + your_response))
reported_tokens = response["usage"]["total_tokens"]

discrepancy = abs(actual_tokens - reported_tokens) / actual_tokens
if discrepancy > 0.1:  # More than 10% off
    print("⚠️ Token count mismatch detected!")

Method 3: Latency Analysis

GPT-4 has a characteristic response time profile. If your "GPT-4" endpoint responds as fast as GPT-3.5-turbo — consistently — that's suspicious. Frontier models are slower. Way slower.

Benchmark against the official API and compare:

  • GPT-4: ~15-30 tokens/second
  • GPT-3.5-turbo: ~80-120 tokens/second
  • GPT-4o: ~60-100 tokens/second

If your "GPT-4" is cranking out 100+ tokens/second, you're probably getting GPT-3.5.

Method 4: Behavioral Testing

Different models have different capabilities. Design tests that only a specific model can pass:

# GPT-4 can handle this; GPT-3.5 typically can't
test_prompt = """
A bat and ball cost $1.10 in total.
The bat costs $1.00 more than the ball.
How much does the ball cost?
Think step by step.
"""

# GPT-4: $0.05 (correct)
# GPT-3.5: $0.10 (wrong, most of the time)
